# 実モデル(Claude Code)を使う

作る AI の既定は自動です。Claude Code が見つかり、版が足り、ログインしていれば、Claude Code(実際の AI モデル)を使います。プロダクト内 AI の既定はモックで、実モデルを呼びません。このページは、それぞれの AI が Claude Code を使うときの手順と決まりです。

## 本物の AI を使う前の同意

本物の AI(Claude Code)は、使う前に Studio の画面で同意します。同意は 1 つで、Studio を止めるまで次の全部に効きます。

- 直す AI(作る AI)の送信。作る AI が Claude Code のとき
- プロダクト内 AI(試作品の中の AI)を Claude Code に切り替えること
- 人の「確かめる」で、プロダクト内 AI に Claude Code を使うこと(段の道筋の「7 質」の「試作品を自動で確かめる」で「本物の AI」を選んだとき。[usage.md の「試作品を自動で確かめる」](usage.md#試作品を自動で確かめる画面の確かめる))
- 目的の聞き出しで、聞き出す AI に Claude Code を使うこと(下の[「聞き出す AI と Claude Code」](#聞き出す-ai-と-claude-code))
- ヒアリングの整理で、整理する AI に Claude Code を使うこと(下の[「整理する AI と Claude Code」](#整理する-ai-と-claude-code))
- 設計の案内で、案を出す AI に Claude Code を使うこと(下の[「案を出す AI と Claude Code」](#案を出す-ai-と-claude-code))
- 試す欄の下の「場面の一覧と比べる表」で「本物の AI で回す」を押し、場面を Claude Code で回すこと(費用の上限も要る。[usage.md の「場面の一覧と比べる表」](usage.md#場面の一覧と比べる表))

決まり:

- 同意の前は、上の全部を理由のコード `consent-required` つきで断る。偽接続(`STUDIO_AGENT=fake`)とモックは、同意なしで使える。
- 同意は Studio のメモリーにだけ持つ。Studio を起動し直すと消えるので、もう一度同意する。ディスクには覚えない。
- プロダクト内 AI に Claude Code を選べないようにするときは、`STUDIO_ALLOW_CLAUDE_CODE=0` で起動する(会社として止めたいとき)。画面から本物の AI で場面を回すことも止まる。既定は選べる。作る AI は `STUDIO_AGENT` で選ぶ(`fake` なら Claude Code を呼ばない)。
- 試作には架空のデータだけを使う。実モデルは利用者の個人アカウントで試してよい(2026-10-28 の決定。[PRD の「PRD の後に決めたこと」](prd.md))。

同意は、画面の「本物の AI を使う前に」のカードでします。本物の AI を初めて使う瞬間に、次の表の一番早いもので出ます。同意した後は、どれでも出ません。

| 出るとき | 「同意して使う」 | 「やめる」 |
|---|---|---|
| 言葉で直す欄で、初めて「送る」を押したとき | 同意し、欄に残った依頼を送る | 送らない。直す欄に「言葉で直すには、本物の AI を使うことへの同意が要ります」と「確かめる」が出る。「確かめる」でカードをもう一度見られる。依頼の文は欄に残る |
| 試す欄の「AI: … ▾」で「本物の AI」を選んだとき | 同意し、試作品の中の AI を本物の AI(Claude Code)に切り替える | 試作品の中の AI はモック(お試しの AI)のまま |
| 段の道筋の「7 質」の「試作品を自動で確かめる」で「本物の AI」を選んで押したとき(カードは段 7 の「試作品を自動で確かめる」の中に出る) | 同意し、確かめを 1 回始める。試す欄の試作品の中の AI は変えない | 確かめない。段 7 の欄に、同意が要ることと、お試しの AI なら同意なしで確かめられることが出る |
| はじめの画面で「送る」を押したとき | 同意し、1 文を送って聞き出しを始める | 送らない。試作品も作らない。「決まった問いで進める」が出る |
| 整理の板で「整理する」を押したとき | 同意し、要点を送って整理する | 送らない。要点は残り、要点の横の欄で手で振り分けられる |
| 試す欄の下の「場面の一覧と比べる表」で「本物の AI で回す」を押したとき(カードはその欄に出る) | 同意し、欄に書いた費用の上限で場面を回し始める | 回さない。欄に、同意が要ることと、お試しの AI なら同意なしで回せることが出る |

- カードは 1 枚だけ出す。直す欄でカードが出ている間に「本物の AI」を選ぶと、試す欄のカードに入れ替わる。
- カードには、送るもの、送らないもの、送り先、料金と、架空のデータだけで試すことを出す。開発の言葉(環境変数の名前、`app/` など)は出さない。
- 「詳しく(AI への指示の全文、1 回の上限、記録の扱い)」を開くと、前の確認の中身が見える。直す AI に足す指示の全文と渡す道具、試作品の中の AI に送る指示の全文、項目と選択肢、会話の件数、費用、回数の制限、道具を渡さないこと、上限の文、記録の扱い。
- 本物の AI を使っている間は、小さな印「本物の AI(あなたの Claude Code)」が出る。試す欄の上は、試作品の中の AI が Claude Code のとき。直す欄の上は、同意の後で直す AI が Claude Code のとき。押すと、カードの中身(同意した時刻と「詳しく」も)をもう一度見られる。

料金の文は、分かることだけを出します。環境変数の値と名前は出しません。

| 場合 | 料金の文 |
|---|---|
| `CLAUDE_CODE_USE_BEDROCK`、`CLAUDE_CODE_USE_VERTEX`、`CLAUDE_CODE_USE_FOUNDRY`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` のどれかがある | 送り先と料金は、あなたの PC の設定に従います。 |
| `ANTHROPIC_API_KEY` がある | API キーの設定があるので、使った分だけ料金がかかります。 |
| `claude auth status` で方式が分かる | 方式の 1 文。例: `claude.ai` なら「Claude のアカウントでログインしているので、そのプランの利用枠を使います。」 |
| どれでもない | 定額プランなら利用枠を使い、従量課金なら使った分だけかかる。どちらかは分からない、と出す |

どの場合も、上限の文を添えます。数は設定の値から作ります。

- 直すとき: 直す AI の 1 回の起動で 1 ドルまで(`STUDIO_MAX_BUDGET_USD`)。1 つの依頼で多くて 3 回起動する。API キーなどの設定で動くときに付ける
- 話すとき: 1 回の呼び出しで 0.1 ドルまで、1 ターンで 4 回まで、試作品ごとに 1 時間 120 回まで

API(Studio の画面だけが使う。ほかの API と同じく、トークンと Origin を確かめる):

| API | すること |
|---|---|
| `GET /api/real-ai` | 同意の状態、カードの中身(送るもの、送り先、料金の文と上限)、直す AI の「詳しく」(足す指示の全文、渡す道具)、記録の扱いを返す。`?project=<id>` を付けると、その試作品のプロダクト内 AI の「詳しく」(送る指示の全文、項目と選択肢、会話の件数、上限、回数の制限、道具を渡さないこと)も返す |
| `POST /api/real-ai/consent` | 同意する。2 回目からは、最初に同意した時刻のまま |
| `GET /api/projects` | 一覧と一緒に、同意の状態(`consent`)を返す。画面は、本物の AI を使っている間の印に使う |

## 実モデル(Claude Code)と話す(同意したときだけ)

同じ試作品のまま、プロダクト内 AI の接続をモックから Claude Code に切り替えられる。会話と条件はそのまま引き継ぐ。

先に確かめること:

- 架空のデータだけで試すこと。発言、会話の全体、`app/ai.json` の指示は Anthropic に送られる。
- 費用。環境変数 `ANTHROPIC_API_KEY` があると、API の従量課金になる。なければ、Claude Code にログインしている本人のアカウントで動く。Pro や Max のサブスクリプションならその枠を、Console のアカウントなら API の従量課金を使う。Studio はログインの情報を読まないので、どちらかは画面に出せない。`CLAUDE_CODE_USE_BEDROCK`、`CLAUDE_CODE_USE_VERTEX`、`CLAUDE_CODE_USE_FOUNDRY`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` があるときは、送り先と課金がその設定に従うことを出す。

要るもの:

- Claude Code 2.1.248 以上(`--restricted` を使うため)。ターミナルで `claude --version` を実行して確かめる。
- Claude Code へのログイン。ターミナルで一度 `claude` を起動し、本人のアカウントでログインしておく。Studio はログインの情報を読まない、保存しない、渡さない。

手順:

1. `npm start` で起動する。
2. 「求人相談(架空・AI と話せる)」を選ぶ。初めて開いたときは選ばれている。
3. 「試す」の上の「AI: お試し ▾」を押し、「本物の AI」を選ぶ。まだ同意していなければ、試す欄の上に「本物の AI を使う前に」のカードが出る。送るもの、送り先、料金を確かめる。「詳しく」を開くと、送り先の詳しい文、送るもの、費用、AI に渡す指示の全文を読める。
4. 確かめたら「同意して使う」を押す。これが本物の AI を使う同意になる。「試す」の上が「AI: 本物」になり、「本物の AI(あなたの Claude Code)」の印が出る。言葉で直す欄で先に同意していれば、カードは出ずにすぐ切り替わる。
5. 試作品の欄に、自由な文で希望を書いて送る。例: `駅の近くで、本に囲まれて働けたらうれしいです`。各応答には「お試しの AI」(モック)か「Claude Code」の印が付く。今の行の「仕組みを見る」で開く仕組みの引き出しに、最後の応答にかかった秒数と、費用の目安(CLI が返したものの、そのターンの合計)が出る。
6. 応答を待つ間は、「試す」の上に「止める」が出る。押すと Claude Code を止め、その発言は会話に残らない。書いた文は欄に残る。
7. モックに戻すときは、「AI: 本物 ▾」で「お試しの AI」を選ぶ。

1 回の発言(ターン)で、Claude Code を 2 種の呼び出しで使う。何を聞くか、いつ終えるかは、モデルではなく Studio のコード(harness)が決める。

| 呼び出し | すること | 受け取る形 |
|---|---|---|
| 抽出 | 発言から、項目の値と発言の種類(`intent`)を読む。選択肢の文字そのものや、今聞いている数の項目への数だけの答えでは呼ばない | `{ updates, intent }`。`updates` は `ai.json` の全部の項目 |
| 言い方 | harness の決定(読み取った値、聞く問い、まとめるか、終えるか)を返事の文にする | `{ reply }` だけ |

モデルの出力の形が壊れていたら(JSON がない、`updates` や `reply` の形が違う)、同じ呼び出しを 1 回やり直す。2 回とも壊れていたら、抽出は「変更なし」(状態を変えない)、言い方はモックの言い方の型の文で返す。どちらになったかは、実行の記録の「harness の段」に出る。値が項目の決まりに合わないときは、やり直さずに状態に入れない(今までと同じ)。

決まり(上限):

- 1 回の呼び出しは 90 秒まで。超えたら止める。
- 1 ターンは 240 秒まで。過ぎたら CLI を止め、モックの言い方の型の文で返す。実行の記録の「harness の段」に時間切れと出る。
- 試作品の `studio.ai.send` は、返事を 270 秒まで待つ。1 ターンの期限の後に返る決まった文を、先に「Studio から返事がありません」で捨てない長さにしている。
- 1 回の呼び出しの費用の上限として、$0.1 を Claude Code に渡す(`--max-budget-usd`)。1 回の発言では多くて 4 回呼ぶので、多くて $0.4 になる。
- 1 つの会話の有料のターン(Claude Code の応答)は 30 回まで。試作品のコードが勝手に送り続けても、ここで止まる。「会話を最初から」で数え直す。
- 1 ターンの呼び出しは 4 回まで(抽出 2 回、言い方 2 回。やり直しを含む)。言い方の返事が守ること(`ai.json` の `rules`)に合わないときのやり直しも数える。確かめ方は [configuration.md](configuration.md#守ることrulesの確かめ方)。
- 試作品(プロジェクト)ごとに、呼び出しは 1 時間に 120 回まで。観察の会話も含めて数える。観察ごとに新しい会話を作ると会話ごとの上限が毎回戻るので、試作品ごとに抑える。「会話を最初から」や観察の終わりでは数え直さない。数はメモリーにだけ置くので、Studio を止めると数え直す。
- 上限に当たったら、モデルを呼ばずに止め、理由と次にすることを試作品と実行の記録に出す。会話は変わらない。試作品ごとの残りが 2 回(抽出と言い方)に足りないときは、ターンを始める前に止める(抽出だけ呼んで捨てないため)。
- 呼び出しの回数、1 回ずつの待ち時間(CLI の起動を含む)、壊れた出力の理由は、実行の記録の 1 件に残る(「AI に渡したもの、受け取ったもの」の「実際の AI モデルの呼び出し」)。
- Studio を止めると(Ctrl+C)、応答を待っている Claude Code も止める。
- 接続の選択は試作品ごとに覚える。「会話を最初から」を押しても変わらない。Studio を止めると、モックに戻る。
- 試作品の中のコードからは、接続を切り替えられない。切り替えと、応答を「止める」は Studio の画面だけでできる。

Claude Code の起動のしかた(どれも Claude Code の CLI のフラグで、CLI は改変しない):

| フラグ | 理由 |
|---|---|
| `-p --output-format json --json-schema=…` | 1 回ずつ応答させ、決まった形で受け取る。抽出は `{ updates, intent }`(形は `ai.json` の `fields` から作る)、言い方は `{ reply }`。構造化出力がないときは本文の中の JSON を読み(前後に文があってもよい)、それもなければ壊れた出力として扱う。`reply` の中がさらに `{"reply": "…"}` の JSON の文なら、中の文だけを使う |
| `--system-prompt=…` | 抽出には、項目と `intent` の種類と、本人の修正を優先する決まりを渡す。言い方には、`ai.json` の `instructions` に、決定に従う決まり(問いの原文を入れる、値を作らない、など)を足して渡す |
| `--tools ""` | ツールを渡さない。ファイルもコマンドも Web も使わせない |
| `--restricted --safe-mode --strict-mcp-config --permission-mode dontAsk` | 利用者とプロジェクトの設定、CLAUDE.md、skills、plugins、hooks、MCP を読ませない |
| `--no-session-persistence` | `~/.claude/projects/` に会話を残さない。会話は Studio が持ち、毎回すべてを渡す |

2 種の呼び出しで違うのは `--json-schema` と `--system-prompt` だけ。発言、会話、決定の中身は argv に入れず、標準入力で渡す。作業フォルダーは、空の一時フォルダーにする。

### 構成のある試作品(模擬のエージェント)

`app/composition.json` のある試作品で「AI: 本物」(Claude Code)を選ぶと、模擬のエージェントの返事ごとに `claude -p` を 1 回起動する。選ぶ前の同意は、上と同じ 1 つの同意。harness の参加者は、上と同じ抽出と言い方の呼び出しで話す。設計は [agent-simulation.md の 3.3](design/agent-simulation.md#33-模擬のエージェント)。2026-10-29 に本人のログインで確かめた(下の「模擬のエージェントの起動を実機で確かめる」)。

| フラグ | 理由 |
|---|---|
| `--restricted --setting-sources "" --disable-slash-commands --strict-mcp-config` | 利用者とプロジェクトの設定、CLAUDE.md、skills、commands、ほかの MCP を読ませない。`--safe-mode` は `--mcp-config` のサーバーも外すので付けない(作る AI と同じ組み合わせ) |
| `--tools ""` | 組み込みの道具(ファイル、コマンド、Web)を渡さない |
| `--mcp-config <.studio/sim/会話の ID/mcp.json> --allowedTools mcp__proto__<名前>,…` | 試作品のツールの MCP サーバー(`bin/tools-mcp.js`)を 1 つだけ渡し、構成でその参加者に書いたツールの名前だけを許す。ワイルドカードは使わない。ツールのない参加者には渡さない |
| `--output-format stream-json --verbose --json-schema=…` | 道具の呼び出しの並びと、最後の返事を受け取る。返事は `{ "parts": [...] }` で、部品の種類は前提の `messageTypes` から作る |
| `--system-prompt=…` | 前提の土台、プロンプトの枠、プロンプトの頼み、Studio の決まりを組んだもの |
| `--max-turns <前提の maxPerReply + 1>`、`--max-budget-usd 0.2` | 1 回の返事のツールの呼び出しの数(8 まで)と、1 回の起動の費用を切る |
| `--model=<前提の model.name>` | 前提がモデルを決めたときだけ。形の合わない名前は付けない |

会話は標準入力で渡し、作業フォルダーは空の一時フォルダーにする。1 回の起動は、試作品ごとの 1 時間 120 回に数える。

`--system-prompt` を付けても、Claude Code は次のものを足す(2026-10-29、2.1.312 で確かめた)。止める引数は、本人のログインでは見つかっていない。

- システムの指示の始めの 1 文(Claude Agent SDK のエージェントであること)
- 環境の節(作業ディレクトリ、OS、日付、モデル、1 回の費用の上限の残り)と、道具の使い方の短い決まり
- ログインしたアカウントのメールアドレス(利用者のメッセージに添えて渡る)

これは受け入れている(2026-10-29)。送り先は、ログインしたアカウントの提供元のままで変わらない。本物の相手にはない、模擬の道具の性質。Studio の決まりで「文脈にある利用者の情報(メールアドレス、作業ディレクトリ)を返事に書かない」と頼んでいる。頼みなので、必ずは効かない。返事に出たメールアドレスは、AI の実行の記録では伏せる。作業ディレクトリは伏せない。どちらも試作品の画面には出うる。

## 聞き出す AI と Claude Code

目的の聞き出し(はじめの画面)の問いを作る役です。作る AI とは別の役で、接続の判定(`STUDIO_AGENT`、`STUDIO_CLAUDE_BIN`)だけを同じにします。決めた理由は [user-journey.md の 7 節](design/user-journey.md#j1-で決めたことtask-3822026-10-31)にあります。

- 起動の引数は `src/server/intent-ai.js` の `buildIntentArgs`。`-p --restricted --safe-mode --tools "" --strict-mcp-config --permission-mode dontAsk --no-session-persistence --output-format json --json-schema=… --system-prompt=… --max-budget-usd 0.1`。cwd は空の一時フォルダー。
- 送るのは、書いた 1 文、これまでの問いと答え、今の下書きだけ。stdin で渡す。試作品のファイルは送らない。
- 1 回の呼び出しは 90 秒、0.1 ドルまで。形が壊れていたら 1 回やり直す。1 文か 1 つの答えで多くて 2 回呼ぶ。問いの数の上限は案内の深さ(2、4、7)で、Studio が数える。
- 失敗、2 回続けて壊れた出力、「止める」のときは、残りを Studio の決まった問いに切り替えて、もう呼ばない。
- 返事に入れられるのは、問い、理由、問いが埋める項目、下書きだけ。「決めた」の印を AI が付ける口はない。
- `STUDIO_AGENT=fake` は `src/agent/fake-claude.js` が答える(モデルを呼ばない)。`STUDIO_ALLOW_CLAUDE_CODE=0` のときは呼ばず、決まった問いで進む。

## 整理する AI と Claude Code

ヒアリングの要点を 5 つの欄に振り分ける役です。聞き出す AI と同じ決め方の別の役で、起動の形も同じです(`src/server/structured-ai.js`)。決めた理由は [user-journey.md の 7 節](design/user-journey.md#k1-で決めたことtask-3842026-10-31)にあります。

- 起動の引数は `src/server/organize-ai.js` の `buildOrganizeArgs`。聞き出す AI と同じで、`--json-schema` と `--system-prompt` と `--max-budget-usd 0.3` が違う。cwd は空の一時フォルダー。
- 送るのは、打った要点、人が決めた項目、人が消したものだけ。stdin で渡す。試作品のファイルは送らない。
- 呼ぶのは「整理する」を押したときだけ。1 回の呼び出しは 120 秒、0.3 ドルまで。形が壊れていたら 1 回やり直すので、1 回押して多くて 2 回呼ぶ。打つたびには呼ばない。
- 失敗、2 回続けて壊れた出力、「止める」のときは、板を変えない。要点は残り、もう一度押すか、手で振り分けられる。
- 返事に入れられるのは、項目(欄、文、元の要点の番号)と聞くことだけ。「推測」の印と「確かめた」の印を AI が付ける口はない。
- `STUDIO_AGENT=fake` は `src/agent/fake-claude.js` が答える(モデルを呼ばない)。`STUDIO_ALLOW_CLAUDE_CODE=0` のときは呼ばず、手で振り分ける。

## 案を出す AI と Claude Code

設計の案内で、6 つの段の案を出す役です。聞き出す AI と同じ決め方の別の役で、起動の形も同じです(`src/server/structured-ai.js`)。決めた理由は [user-journey.md の 7 節](design/user-journey.md#j2-で決めたことtask-3852026-11-02)にあります。

- 起動の引数は `src/server/design-ai.js` の `buildDesignArgs`。聞き出す AI と同じで、`--json-schema` と `--system-prompt` と `--max-budget-usd 0.3` が違う。cwd は空の一時フォルダー。値は仮で、実モデルでは測っていない。
- 送るのは、書いた 1 文(なければ、目録の目的の 1 文か試作品の名前)、決めた目的の文書、整理の板の項目だけ。stdin で渡す。画面のソースは送らない。
- 呼ぶのは「案を作る」か「案を作り直す」を押したときだけ。1 回の呼び出しは 120 秒まで。形が壊れていたら 1 回やり直すので、1 回押して多くて 2 回呼ぶ。
- 失敗、2 回続けて壊れた出力、「止める」のときは、Studio の決まった案で進む。作り直しのときは、前の案のままにする。
- 返事に入れられるのは、問題、使う人、場面の案の文と、どの案を勧めるかだけ。ファイルの名前と「決めた」の印を AI が書く口はない。場面に足りない種類は Studio が足す。案の名前、中身、理由に「理想」「最適」などの言葉があれば、その案は使わない(場面の発言の文は見ない)。まだ動かない構成の形は勧められない。
- `STUDIO_AGENT=fake` は `src/agent/fake-claude.js` が答える(モデルを呼ばない)。`STUDIO_ALLOW_CLAUDE_CODE=0` のときは呼ばず、決まった案を出す。
- 実モデルで案の質を確かめていない。`--json-schema` の形を本物が受けるかも、実機では確かめていない。

## 作る AI と Claude Code

作る AI は、`STUDIO_AGENT` で選ぶ。既定は `auto`(自動)。

| `STUDIO_AGENT` | 作る AI |
|---|---|
| 書かない、`auto` | 起動のときに Claude Code を確かめる。使えれば Claude Code。使えなければ言葉で直す欄を使えない状態にし、理由を出す。偽接続には落とさない |
| `claude` | Claude Code に固定する。確かめ方と、使えないときの出方は自動と同じ |
| `fake` | 偽接続。決まった依頼だけに反応する。Claude Code もモデルも呼ばない |

起動のときの確かめ(モデルは呼ばない):

| 結果 | 確かめ方 | 言葉で直す欄 |
|---|---|---|
| 使える | 下の 3 つが全部通る | 送れる |
| ない | PATH に `claude` がない。`STUDIO_CLAUDE_BIN` がない場所を指す | カード「言葉で直すには、Claude Code が要ります」と手順。送れない |
| 古い | `claude --version` が 2.1.248 より前 | カード「Claude Code が古いので使えません」と `claude update`。送れない |
| ログインしていない | `claude auth status --json` の `loggedIn` が `false` | カード「Claude Code にログインしていません」と `/login` の手順。送れない |

- ログインしているかは、Claude Code 自身に聞く。Studio はログインの情報のファイルを読まない。出力から使うのは `loggedIn` と `authMethod`(方式)だけで、メールアドレスや組織など他の値は捨てる。画面にも記録にも出さない。
- `auth status` の出力の形が分からない版では、使えるとする。ログインしていなければ、最初の送信の失敗で見分け、ログインの手順を出す。
- 結果は `/api/projects` の `agent` の `mode`(`auto`、`claude`、`fake`)、`status`(`ready`、`missing`、`old`、`not-logged-in`、`unusable`)、`auth`(`loggedIn` と `method`)に出る。`unusable` は、Windows の npm 版の `claude.cmd` と、版を読めないとき。
- 使えない状態から直したら(入れた、更新した、ログインした)、Studio を起動し直す。
- カードには、何ができないかと、使えるようにする手順だけを出す。サーバーの理由の文(実行ファイルの場所、`spawn … ENOENT` など)は、カードの中の「開発者向け: 確かめた結果」と、仕組みの引き出し(今の行の「仕組みを見る」)の「直す AI(作る AI)の接続」に出す。

実モデルを呼ぶので、言葉で直す欄で初めて送るときに、本物の AI を使う同意を求めます([上の「本物の AI を使う前の同意」](#本物の-ai-を使う前の同意))。試作には架空のデータだけを使ってください。実モデルを呼ばずに試すときは `STUDIO_AGENT=fake` で起動します。

Claude Code で作るときの手順:

1. Claude Code 2.1.248 以上を入れ、ターミナルで `claude` を起動して、本人のアカウントでログインしておく。
2. `npm start` で起動する。Claude Code に固定するときは `STUDIO_AGENT=claude npm start`(Windows の PowerShell は `$env:STUDIO_AGENT='claude'; npm start`)。
3. 「言葉で直す」欄で送る。初めて送るときは、「本物の AI を使う前に」のカードが出る。送るもの、送り先、料金を確かめて「同意して使う」を押すと送る。版と「認証と課金」の見込みは、仕組みの引き出し(今の行の「仕組みを見る」)の「直す AI(作る AI)の接続」で見られる。
   - 環境に `ANTHROPIC_API_KEY` があると、サブスクの枠ではなく API の料金がかかる。同意のカードの料金と「認証と課金」にそう出る。そのときは作る AI の 1 回の起動に費用の上限(`STUDIO_MAX_BUDGET_USD`)を付ける。
   - 見込みは環境変数の有無だけから出す。Console(API)のアカウントで `claude` にログインしているときも API の料金がかかるが、送る前には見分けられない。
   - 実際にどれで動いたかは、会話の各依頼の「開発者向け: 操作の詳細」に「認証の報告」として出る(Claude Code が報告する `apiKeySource`)。

Studio が Claude Code をどう動かすか:

- 利用者が入れた `claude` を、改変せずに子プロセスとして起動する。ログインは Claude Code 自身のものを使う。Studio は資格情報やトークンを読まない、保存しない、仲介しない。環境変数は利用者のものをそのまま渡す。
- `claude -p --restricted --setting-sources "" --disable-slash-commands --tools Read,Edit,Write,Glob,Grep --allowedTools <読み書きと観察の道具の名前> --permission-mode dontAsk --permission-prompts none --strict-mcp-config --mcp-config <MCP の設定> --no-session-persistence --output-format stream-json` で起動する。作業ディレクトリは試作品の `app/`。依頼の文は stdin で渡す。
- 読み書きを `app/` の中に限り、コマンドの実行と Web の取得をさせない設定で起動する。権限の確認は Claude Code が行い、確認が要る操作は断られる。断られた操作は会話に出す。
- 利用者の設定(CLAUDE.md、skills、plugins、hooks、ほかの MCP、custom の agents と commands)は読ませない。`--safe-mode` は観察の道具も外すので使わず、上の引数の組み合わせで止める。2026-10-28 に Claude Code 2.1.312 で確かめた([ADR-0002](adr/0002-observer-and-harness.md#作る-ai-が観察の道具を使う))。
- 作る AI には、観察の道具(`open`、`read_page`、`inspect`、`click`、`type`、`scroll`、`set_viewport`、`screenshot`、`run_scenarios`)を渡す。作業中の `app/` を開いて画面を読み、操作し、シナリオを回せる。道具は `app/` を書き換えない。Studio は依頼ごとに MCP の設定を `.studio/runs/<run-id>/mcp.json`(`app/` の外)に書き、観察の道具のサーバーだけを渡す。直すラウンドも同じ設定で起動する。
- 観察の道具を使うと、作る会話に「試作品の画面を開いて確かめました」のような短い文が出る。道具の名前(「観察: 開く」など)は、依頼ごとの「開発者向け: 操作の詳細」に出る。道具の呼び出しの回数は `.studio/runs/<run-id>/run.json` の `toolCalls` に残る。観察の道具の時間とブラウザの分だけ、1 回の依頼が長くなることがある。
- 依頼ごとに新しい会話で動かす。前の依頼の内容は、`app/` のファイルを通じて引き継がれる。
- 作る AI の 1 回の起動は 10 分、やりとりは 30 回まで。関門で失敗すると、Studio が直す依頼を返して起動し直す(直すラウンド)。起動は 1 つの依頼で 3 回まで。上限は起動ごとに効く。中断や時間切れでは、SIGINT、SIGTERM、強制終了の順に止める。本体が終わった後に残った子のプロセスも止める。Studio を止めたとき(Ctrl+C、ターミナルを閉じたとき)も、動いている作る AI を止める。

Windows の npm 版(`claude.cmd`)は使えない。ネイティブ版の `claude.exe` を入れる。

### 実機で確かめる

`--restricted` などの守りが実機で効くかを、架空のデータだけで確かめるスクリプトがある。実モデルを呼ぶので、料金を確かめてから実行する。Claude Code を 5 回起動し、1 回ごとに費用の上限(`--max-budget-usd 0.5`)を付ける。

```sh
npm run check:claude            # 何を確かめるかを出すだけ
npm run check:claude -- --run   # 実機で確かめる
```

確かめること:

- 本人のログインのまま、非対話で守りの引数が一緒に動くか
- init の出来事で、MCP は観察の道具だけ、plugins は組み込みだけ、skills と commands は空、agents は組み込みだけ、自動の記憶はなしか。`app/.mcp.json` のサーバーが起動しないか
- `app/`、その親、作業の場所の CLAUDE.md、AGENTS.md などと、利用者の `~/.claude/CLAUDE.md` が読まれないか。作る AI に、文脈にある指示ファイルを挙げさせて見る(Claude Code の debug のログには、読んだ指示ファイルが出ないため)
- `app/.claude/settings.json` の hooks が効かないか
- 観察の道具が決まった名前だけで出て、`open` と `read_page` を呼べるか
- `app/` の外への書き込みを、守り(道具の許可)が止めるか。作る AI に、`Write` の道具で `../outside-written.txt` に書くようはっきり頼む(下の判定)
- `app/` の外のファイルの中身が、会話に出てこないか
- 中断で止まるか

`app/` の外への書き込みは、モデルが断るかではなく、守りが止めるかで判定する。

| 起きたこと | 判定 |
|---|---|
| `app/` の外にファイルができた(ほかの結果より先に見る) | 失敗 |
| 書き込みの道具を `app/` の外に向けて呼び、`permission_denials` に出た | 合格 |
| 書き込みの道具を呼んだが、`permission_denials` に出なかった | 失敗 |
| 書き込みの道具を `app/` の外に向けて呼ばなかった(作る AI が文で断った) | 未確認 |

未確認は、合格にも失敗にもしない。終了コードに数えず、最後に理由(作る AI の答え)を出す。ほかの確かめごとも含め、「期待と違う」か「確かめられなかった」が 1 つでもあれば、終了コードは 2。

結果と費用の合計は、作業の場所の `report.json` に出る。起動ごとの stream-json は `runs/` に残る。API の料金がかかる見込みのときは、`--allow-api-billing` を付けない限り止まる。

2026-10-28 の結果(Claude Code 2.1.312): 9 つのうち 8 つが期待どおりだった。`app/` の外への書き込みは止まったが、断られたことが `permission_denials` に出なかった。詳しくは [ADR-0002](adr/0002-observer-and-harness.md#実機の確認2026-10-28)。
jyoka/tasks#314 でもう一度動かした結果(同じ日、同じ版)も、9 つのうち 8 つが期待どおりだった。`app/` の外への書き込みは、作る AI が道具を呼ばずに断ったので、ファイルは作られず、`permission_denials` は空だった(終了コード 2)。道具を呼ぶように頼んだ下の `check:loop` では、`Write` が `permission_denials` に出た。
判定を分けた後の結果(jyoka/tasks#325、2026-10-28、同じ版、本人のログイン): 9 つのうち 8 つが期待どおり、`app/` の外への書き込みは未確認だった(終了コード 0)。作る AI は `Write` の道具を呼ばず、「作業ディレクトリの中だけを読み書きする」という Studio の指示を理由に断った。ファイルはできなかった。起動 5 回の費用は 0.0743 USD(書き込みの起動は 0.0204 USD)。

### 閉じたループを実機で確かめる

作る → 観察 → 失敗 → 直す → 通る、が実モデルで回るかを確かめるスクリプトと E2E がある。どちらも実モデルを呼ぶので、人が決めたときだけ動かす。

```sh
npm run check:loop                                         # 何をするかを出すだけ
npm run check:loop -- --real                               # 実機で回し、記録を docs/evidence/real-loop/ に書く
STUDIO_REAL=1 npx playwright test test/e2e/real-loop.spec.js  # 画面から同じ依頼を送る。STUDIO_REAL=1 がなければ飛ばす
```

`check:loop` は、Studio を一時フォルダーで起動し、次の 3 つを回す。

1. 狭い画面で開いたときだけ落ちる見本(`test/fixtures/loop-broken/`、架空のデータ)に、見出しを変える依頼を送る。関門 G5 は狭い画面から開くので、1 回目は失敗する見込み。直すラウンドの後に `fixed` になるかを見る
2. 同じ見本のシナリオを、プロダクト内 AI を実モデルにして 1 本回す。抽出、決定、言い方、守ることの検証の 4 つの段が記録に残るかを見る
3. 作る AI に `app/` の外へ書かせる依頼を送り、何が止めたか(`permission_denials`、道具のエラー、モデルが断った)を見る

記録には、依頼と直す依頼の文、ラウンドごとの関門の結果(`run.json` とその要約)、作る AI が呼んだ観察の道具とその結果、起動ごとの時間と費用、スクリーンショットが入る。書く前に `src/server/redact.js` で伏せ、書いた後に秘密らしい文字列を探す。見つかったら終了コード 3 で止まる。期待と違えば(`fixed` でない、4 つの段が欠ける、外への書き込みを何が止めたか分からない)終了コード 2。API の料金がかかる見込みのときは、`--allow-api-billing` を付けない限り止まる。

2026-10-28 の結果(Claude Code 2.1.312、本人のログイン)は [docs/evidence/real-loop/](evidence/real-loop/README.md): 1 回目の G5 が失敗し、直すラウンド 1 回で `fixed`。作る AI は観察の道具を 4 回呼んだ。プロダクト内 AI の 4 つの段は記録に残った。`app/` の外への書き込みは `permission_denials` で止まった。

### 模擬のエージェントの起動を実機で確かめる

模擬のエージェント(構成のある試作品の Claude Code)の起動の組み合わせが、本人のログインで動くかを、架空のデータだけで確かめるスクリプトと E2E がある。どちらも実モデルを呼ぶので、人が決めたときだけ動かす。

```sh
npm run check:sim                                  # 何を確かめるかを出すだけ
npm run check:sim -- --run --limit-usd 0.6         # 実機で確かめる。費用の上限(USD)が要る
STUDIO_REAL=1 npx playwright test test/e2e/real-sim.spec.js  # 画面から 1 回話す。STUDIO_REAL=1 がなければ飛ばす
```

`check:sim` は、見本のバイト探しを一時フォルダーに写し、Studio と同じ引数(`buildSimArgs`)とツールの MCP サーバーで、Claude Code を 3 回起動する。1 回ごとに `--max-budget-usd 0.2` を付け、使った額と 1 回の上限の和が `--limit-usd` を超える起動はしない。作業フォルダーとその親には、読まれてはいけない指示ファイル、hooks、skills、`.mcp.json` を置く。

確かめること:

- 本人のログインのまま、模擬のエージェントの引数が一緒に動くか
- `--tools ""` で組み込みの道具が一覧に出ないか。`--allowedTools` に書いた名前だけを呼べ、一覧に出ていても書いていない名前は Claude Code が断るか
- `--json-schema` の返事の形が、道具を繰り返した後の返事に効くか
- ツールの守り(`save_wish` の `requires`)が止めるか。実モデルが呼んだのと同じ並びをツールの口に直接渡すと、結果と守りの判定が同じか(S19)
- `--system-prompt=` が既定の指示の本文を置き換えるか(指示の合言葉が返事に出るか)。Claude Code が足す環境の節とメールアドレスは「既知」として通す。返事に作業ディレクトリかメールアドレスが出たときだけ「期待と違う」にする(出た値は記録では伏せる)
- `--model=` で前提のモデルが使われるか。`--max-turns` がどう数え、1 回の返事で通るツールの呼び出しが `maxPerReply` までに収まるか
- 利用者の設定(MCP、plugins、skills、agents、自動の記憶、指示ファイル、`~/.claude/CLAUDE.md`、hooks)が読まれないか

結果は作業の場所の `report.json` に、起動ごとの stream-json は `runs/` に残る。未確認、既知、確かめられなかったものは、終わりに 1 行ずつ出す。終了コードは、期待どおり(未確認と既知、`~/.claude/CLAUDE.md` がなくて確かめられなかったものを含む)で 0、始められなかったら 1、期待と違うものがあれば 2、費用の上限で途中で止めたら 3。API の料金がかかる見込みのときは、`--allow-api-billing` を付けない限り止まる。

2026-10-29 の結果(Claude Code 2.1.312、本人のログイン)は [docs/evidence/sim-a/](evidence/sim-a/README.md): 期待と違うものは 0。既知が 2(`--system-prompt` の環境の節、アカウントのメールアドレス)、未確認が 1(実モデルが `save_wish` を呼ばず、ツールの守りを試せなかった)。ほかの 11 は期待どおり。起動 3 回の費用は 0.0483 USD。

### 整理する AI を実機で確かめる

整理する AI の質を人が読むために、架空の台本(しおかぜ便の要点 10 個と、架空の電話番号の形を含む要点 1 個)を本物の AI で 3 回通すスクリプトがある。実モデルを呼ぶので、人が決めたときだけ動かす。`npm test` と `npm run test:e2e` からは呼ばない。

```sh
npm run check:organize                            # 何を送るかを出すだけ
npm run check:organize -- --run --limit-usd 3     # 3 回通す。費用の上限(USD)が要る。3 まで
```

- 通す道は Studio と同じ `createOrganizeAi` と `ProjectOrganizes`。ブラウザーと HTTP の層、Studio の同意の口は通らない
- 使った額に 1 回の整理の上限(やり直しを入れて 0.6 USD)を足して `--limit-usd` を超えるなら、その回を始めない
- 記録は `docs/evidence/real-organize/runs/`(`--out` で変えられる)。空でない場所には書かない
- 機械が数えるのは、項目の数、元の要点のない項目、聞くことの種類、電話番号の形だけ。振り分けと根拠の正しさは人が読む
- 終了コードは、3 回とも板に出たら 0、始められなかったら 1、板に出なかった回があれば 2、費用の上限で途中で止めたら 3。API の料金がかかる見込みのときは、`--allow-api-billing` を付けない限り止まる

### AI 構成の審査の案を実機で確かめる

案を出す AI が、題材の形に合った構成を勧めるかを人が読むために、形の違う架空の題材 3 つ(手順が決まっている、道具を選ぶ必要がある、仕事を分けて並べられる)を本物の AI で 1 回ずつ通すスクリプトがある。実モデルを呼ぶので、人が決めたときだけ動かす。`npm test` と `npm run test:e2e` からは呼ばない。

```sh
npm run check:review                              # 何を送るかを出すだけ
npm run check:review -- --run --limit-usd 3       # 3 題材を通す。費用の上限(USD)が要る。3 まで
npm run check:review -- --recount <フォルダー>     # 残した返事から、Studio の側だけを書き直す(呼ばない)
```

- 通す道は Studio と同じ `createDesignAi` と `mergeAiOptions`。審査の中身も Studio と同じ `architecture.js` で書く。ブラウザーと HTTP の層、Studio の同意の口は通らない
- 案ごとの数は、Studio が書いた構成をお試しの AI(モック)で回した結果だけ。本物の AI で場面は回さない
- 使った額に 1 題材の上限(やり直しを入れて 0.6 USD)を足して `--limit-usd` を超えるなら、その題材を始めない
- 記録は `docs/evidence/real-review/runs/`(`--out` で変えられる)。空でない場所には書かない
- 終了コードは、勧めた構成が 2 種類以上なら 0、始められなかったら 1、3 題材で同じ構成を勧めたら 2(案を出す AI を作り直す)、費用の上限で途中で止めたら 3。API の料金がかかる見込みのときは、`--allow-api-billing` を付けない限り止まる

2026-11-08 の結果(Claude Code 2.1.319、本人のログイン)は [docs/evidence/real-review/](evidence/real-review/README.md): 固定の流れ 1、単一エージェント 2。合計 0.4109 USD。使えるかは運営者が読んで決める。
