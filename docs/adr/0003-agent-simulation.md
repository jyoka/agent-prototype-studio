# ADR-0003: エージェントの構成を模擬する基盤

- 状態: **案**(2026-10-28)。利用者が採るかを決める。設計は [docs/design/agent-simulation.md](../design/agent-simulation.md)
- 出典のタスク: jyoka/tasks#328。関係するカード: jyoka/tasks#327
- 確認日: 2026-10-28。実モデルは呼んでいない。Claude Code の引数の組み合わせのうち、模擬のエージェントで新しく使うもの(`--tools ""` と `--mcp-config` を一緒に使うなど)は確かめていない。設計の sim-7 で確かめる
- 関係: [ADR-0005](0005-ai-architecture-review.md)(案。2026-10-31)が、この土台の上に人の承認を足す。この ADR の決定は変えない。AI 同士の引き継ぎ(`handoffs`)はデータとして残し、審査の選択肢には出さない
- 実機の確認: 2026-10-29(sim-7、Claude Code 2.1.312、本人のログイン)。組み合わせは動いた。`--system-prompt` は置き換えきれないものがあった(下の「残る危険」)。記録は [docs/evidence/sim-a/](../evidence/sim-a/README.md)
- [ADR-0001](0001-local-runtime-and-isolation.md) の 3 つの層と、[ADR-0002](0002-observer-and-harness.md) の観察器の隔離、直すラウンドの回数、作る AI の起動の決まりは変えない。作るループには関門を 1 つ足す(下の「変える今の決まり」)

## 背景

- 運営者は、仕事の POC(LINE のトークの中で、相手の会社の AI エージェントが会話を回し、DIP がツール、データ、プロンプトの一部、ガードレールを出す形)を Studio で試したい
- 今の Studio のプロダクト内 AI は、Studio の harness が会話を回し(S16)、ツールを持たない(S10)。外のエージェントが DIP のツールを呼ぶ形は表せない
- 運営者の求め(2026-10-28、要約): 外のエージェントは、Studio の中で模擬すればよい。一番大事なのは、一度入れたら、ほかのエージェントのツールやプロトタイプも同じ基盤で模擬し、効果を試せること。流用できるかが、評価の点であり設計の点

## 決定(案)

| 決めたこと | 中身 |
|---|---|
| 構成をデータにする | 試作品の中の AI を、`app/composition.json` に書く構成として扱う。回し手、参加者(`agent`、`harness`、`human`)、ツール、プロンプトの枠、ガードレール、会話の枠、前提を表す |
| 構成 B は今のまま | `composition.json` のない試作品は、`ai.json`(版 2)の harness 1 つの構成として読む。`ai.json` の版は上げない。`studio.ai` の返す会話の形も今のまま |
| 流用を受け入れ条件にする | 形の違う 3 つの構成(A、B、C)を、Studio のコードを変えずにデータだけで表す。新しい構成を足す変更で `src/` と `bin/` が変わらないことを、カードで確かめる |
| ツールは宣言 | 試作品のツールは `app/tools.json` に、決まった 5 つの処理(`search`、`get`、`record`、`fixed`、`handoff`)で書く(後に #420 で `delegate`、#421 で文書の検索の `retrieve` を足し、7 つになった)。Studio のコード(ツールの口)が解釈する。データは `app/` の中の JSON だけを読む |
| ツールを MCP で出す | ツールの口を、stdio の MCP サーバー(`bin/tools-mcp.js`、サーバーの名前は `proto`)として出す。模擬のエージェントには `--mcp-config` で 1 つだけ渡し、構成に書いた名前だけを `--allowedTools` に並べる |
| 模擬のエージェント | Claude Code を、返事ごとに 1 回起動する。組み込みの道具は渡さない(`--tools ""`)。`--safe-mode` の代わりに ADR-0002 の案 5 の組み合わせを使う。cwd は空の一時フォルダー。会話は Studio が持ち、stdin で渡す |
| 前提を差し替えられる | 相手の仕様の分からない所(モデル、プロンプトの土台と枠の長さ、メッセージの種類、ツールの呼び方と認証、記録の取り方)は、`app/assumptions/*.json` にだけ置く。記録に前提の `id` と指紋を残す |
| ガードレールの 3 つの層 | ツールの守り(ツールの口が守る。必ず効く)、プロンプトの頼み(相手しだい)、出口の確かめ(持ち主が本番で持てるときだけ止める。持てなければ記録だけ)。どの層が効いたかを記録に残す |
| 場面の回しは関門と分ける | ツールだけの場面とモックの場面は、新しい関門 GE(G4 の後、G5 の前)で回す。実モデルで場面を回すのは `npm run evals -- --real` だけで、費用の上限がなければ始めない。task 423 で、Studio の主の画面からも回せるようにした。画面の口は、同意のカード(下の C5a の行の「画面の同意を通る口」)と費用の上限を通す([ai-architecture-review.md の 15 節](../design/ai-architecture-review.md#15-423-で決めたこと)) |

## 変える今の決まり

| 今の決まり | どう変えるか | 理由 |
|---|---|---|
| S10「プロダクト内 AI には道具を渡さない」(harness.md の 1.2、ADR-0001 の #277) | 構成 B(harness の参加者)は今のまま。固定の流れ(設計の 2.8。#419)でも、ツールを呼ぶのはコードで、モデルには渡さない。模擬のエージェント(`agent` の参加者)には、構成に書いた試作品のツールだけを、1 つの MCP サーバーから名前を並べて渡す。組み込みの道具は渡さない | 外のエージェントがツールを選ぶ形を模擬するには、ツールが要る。渡すものは決まった処理の宣言だけで、被害の範囲は記録の店とデータの読み出しに収まる |
| S16「何を聞くか、いつ終えるかは `ai.json` とコードが決める」 | 回し手が harness なら今のまま。回し手がエージェントなら、何を聞くかはモデルが決める。誰が話すか、引き継ぎ、上限、ツールを動かすか、ツールが何を返すかは、コードが決める | 本番で DIP は相手のエージェントの流れを決められない。模擬でコードに決めさせると、本番と違うものを測る。DIP が本番で必ず守れるツールの中に、決まった手順の境目を置く |
| プロダクト内 AI の Claude Code の起動(ADR-0001 の #276: `--safe-mode`、`--tools ""`) | 構成 B は今のまま。模擬のエージェントは `--safe-mode` を外し、ADR-0002 の案 5(`--restricted`、`--setting-sources ""`、`--disable-slash-commands`、`--strict-mcp-config --mcp-config`)に `--tools ""` を足す | `--safe-mode` は `--mcp-config` のサーバーも外す(ADR-0002 の実機の確認) |
| harness.md の 6「最初から複数のエージェントにはしない」 | 変えない。あれは Studio の作る側の役割の話。この ADR の複数の参加者は、試作品の中の構成(作る対象)の話 | 混同を防ぐため、ここに書いておく |
| 目録 `prototype.json` の版 1 | 版 2 で `composition`、`compositions`、`evals` のキーを足す。版 1 に書くと誤り | `ai.json` の版 1 と版 2 と同じ決まりにそろえる |
| 作るループの関門の並び(harness.md の 2.1、S11) | ビルド(G4)の後、起動の確認(G5)の前に、関門 GE(場面。ツールだけの場面とモックの会話の場面)を足す。場面のない試作品は「場面なし」で通る。直すラウンドの回数(2 回まで)は変えない | ブラウザを使わないので、G5 と G6 より安い。安い順に回す決まり(S11)のまま |
| AI の実行の記録は、メモリーにだけ置く(ADR-0001 の #277) | 記録はメモリーのまま。足すのは 2 つ。ツールの MCP サーバーが会話の続きをつなぐ作業の場所(`.studio/sim/<会話の ID>/`。会話を最初からにしたとき、版を復元したとき、Studio の起動のときに消す)と、場面の回しの結果(`.studio/evals/`。伏せた形で残す) | MCP サーバーは返事ごとに起動し直すので、続きはファイルでつなぐしかない。場面の回しの結果は、構成と前提を比べるために残す必要がある。中身は架空のデータ、場面に書いた発言、模擬のエージェントの返事だけ |
| 同梱するライブラリは React だけ(ADR-0001 の #273、未決事項「UI 部品まで入れるか」) | 会話の枠の部品 `studio-talk` を足す。Studio のコードとして同梱し、試作品の iframe の中で動く | 会話の枠を構成ごとに差し替えるため。試作品ごとに作る AI がトークの画面を書き直さなくてよい |
| 試作品から呼ぶ口(`studio.ai.send(text)`) | `studio.ai.send(text, { action })` でボタンの `action` を送れる。構成があるときだけ、返る会話に `participants`、`active`、メッセージの `from` と `parts`、`records` を足す。構成 B は今のまま | ボタンとカードの会話の枠を使うため。足すだけなので、今の試作品は変えずに動く |
| ux-redesign.md の C5a(P24)「`STUDIO_ALLOW_CLAUDE_CODE=1` の要件をやめる」(まだ作っていない) | やめるのは画面の同意を通る口だけにする。場面の回し(`npm run evals -- --real`)は、`=1` と `--limit-usd` を要件のまま残す。`=0` で選べなくするのは両方に効かせる。模擬のエージェントの本物への切り替えも、P24 の同意の口を通す | 場面の回しは画面を通らず、同意のカードが出ない。明示の許可と費用の上限がないまま実モデルを呼ばないため |
| harness.md の 8.1「画面のカードは 1 列」と、その順番 | 決まりは変えない。画面に触る sim のカード(sim-10)を、画面の列の P28 と P29 の間に入れる。P29〜P31 は sim のカードを全部待つ(設計の 8.3) | `src/ui/studio.js` の衝突を避け、言葉の総点検とスクリーンショットに新しい画面を入れるため |

## 守りが崩れない理由

| ADR-0001 の決まり、脅威 | この ADR での扱い |
|---|---|
| 生成コードはサーバーで実行しない | ツールは宣言で、処理の種類は Studio のコードが持つ。データは JSON として読むだけ。式、関数、正規表現は書かせない。`.js` のデータは検査の誤り |
| 作る AI が書く値が起動の引数に入る | 前提とツールの値は作る AI が書ける。ツールの名前は `^[a-z][a-z0-9_]{0,39}$` だけにする(`--allowedTools` に並ぶため)。`model.name` は形を決め、`--model=` でつなぐ。数の値(`maxPerReply`、`resultMaxChars`、`delayMs` など)には上限を置く(設計の 3.4) |
| 作る AI の閉じ込め(層 1) | 変えない。作る AI は試作品のツールを持たない。模擬のエージェントは観察の道具とファイルの道具を持たない |
| sandbox の iframe と CSP(層 2) | 変えない。会話の枠は Studio が同梱する部品として、試作品の iframe の中で動く |
| Studio の守り(層 3) | 変えない。ツールの MCP は stdio で、待ち受けのポートを開けない |
| T1(作る AI が `app/` の外へ読み書きする。原因にプロンプトの注入を含む) | 作る AI の守りは変えない。模擬のエージェントは、データに指示が入っても、使えるのは試作品のツールだけ。ツールの守り(形の検査、`requires`、`deny`、回数)の中に収まる。ファイル、コマンド、Web、外への通信の道具はない |
| T2 置かれた設定が命令を動かす | 模擬のエージェントも `--restricted`、`--setting-sources ""`、`--strict-mcp-config` で起動する。cwd は空の一時フォルダー |
| T6 費用 | 起動ごとの `--max-budget-usd`、1 回の返事のツールの数(`--max-turns`)。試す画面ではプロジェクトごとの 1 時間 120 回。場面の回しは Studio の外で動くので、台帳の上限(`--limit-usd`)と起動の数の上限(`--max-launches`) |
| T7 資格情報 | ツールの認証は、会話ごとの架空の利用者の ID だけ。本物の資格情報を使わない |

## 検討した候補

| 候補 | 長所 | 短所 | 判断 |
|---|---|---|---|
| a. 構成をデータにし、ツールは宣言(この ADR) | 新しい構成をデータだけで足せる。ADR-0001 の守りのまま | 処理の種類が 5 つに限られる。足りなければ Studio のコードに足す | **案** |
| b. `ai.json` を版 3 にし、構成も入れる | ファイルが 1 つで済む | 構成 B の試作品まで書き直しが要る。harness の中身と「誰が回すか」が混ざる | 採らない |
| c. ツールを生成コード(JS)で書き、Node の `vm` や worker で動かす | 何でも書ける | ADR-0001 の「生成コードはサーバーで実行しない」に反する。`vm` は隔離の仕組みではない | 採らない |
| d. ツールを生成コードで書き、ブラウザ(観察器の文脈か試作品の iframe)で動かす | 生成コードはブラウザの中のまま | ツールを呼ぶたびにブラウザが要り、遅い。MCP サーバーとブラウザの中継が要る | 後の候補。宣言で足りないと分かったら考える |
| e. 外のエージェントも harness で模擬する(ツールの呼び出しをコードで決める) | 結果が毎回同じ | 相手のエージェントがツールを選ぶ振る舞いを測れない。POC で知りたいことが分からない | 採らない。モックの模擬のエージェントは、関門とテストのためだけに置く |
| f. ツールの MCP を、Studio の中の loopback の HTTP にする | 記録の店を Studio のメモリーに直接置ける | 待ち受けのポートとトークンが増える | 採らない。stdio とファイルでつなぐ |
| g. 会話の枠を特定のアプリ専用に作る | 見た目が本番に近い | ほかの構成に使えない。他社の見た目を写すことになる | 採らない。汎用の部品 5 つと見た目 3 種にする |

## 残る危険

- 模擬のエージェントは、相手のモデルの代わりに Claude で回す。結果は相手の本番と違いうる。記録と比べる表に「代わりのモデル」と出し、前提でモデルを替えて差を見る
- 出口の確かめ(`noNewNumbers`、`forbidden` など)は形だけを見る。意味までは確かめない(harness.md の 4.5 と同じ)
- 「プロンプトかモデルが止めた」は、頼みが効いたのか、モデルがもとから断ったのかを分けられない。頼みを外した回し直しで差を見る
- 採点(LLM の採点)のモデルが模擬のエージェントと同じ Claude だと、偏りが出うる(推測)。コードの確かめと並べて読む
- `--tools ""` と `--mcp-config`、`--json-schema` と道具の繰り返し、`--model` の組み合わせは、sim-7 で本人のログインで動いた(`npm run check:sim -- --run`)。Claude Code の版を上げたら回し直す
- `--system-prompt` を付けても、Claude Code は始めの 1 文、環境の節(作業ディレクトリ、OS、日付など)、ログインしたアカウントのメールアドレスを、模擬のエージェントの文脈に足す(sim-7 で確かめた)。止める引数は本人のログインでは見つからなかった。受け入れた(2026-10-29)。送り先は利用者のアカウントの提供元のままで、外に出ないため。本物の相手にはない、模擬の道具の性質として扱う。Studio の決まりで「返事に書かない」と頼むが、必ずは効かない。返事に出たメールアドレスは、記録では伏せる。作業ディレクトリは伏せない。どちらも試作品の画面には出うる(設計の 3.3)
