# #420 の実機: マスターとサブを、固定の流れ、単一エージェントと同じ場面の一覧で比べる

見本「しおかぜ便の再配達(架空)」の場面 10 本を、3 つの形で 1 回ずつ回した記録です。2026-11-07 に、本人のログインの Claude Code で取りました。

- 形は 3 つ。固定の流れ(`composition.json`)、単一エージェント(`compositions/single-agent.json`)、マスターとサブ(`compositions/master-sub.json`。[agent-simulation.md の 2.9](../../design/agent-simulation.md#29-マスターとサブ親の-ai-が子の-ai-に仕事を任せる))
- Claude Code 2.1.319、本人のログイン(`ANTHROPIC_API_KEY` なし)。`--repeat 1`
- 模擬のエージェントと固定の流れの harness のモデルは、前提 `stand-in` の代わりのモデル `claude-sonnet-5-5`。採点(`judge`)も `claude-sonnet-5-5` で、同じ返事を 2 回ずつ採点した
- データ、荷物、宅配の会社は、どれも架空。記録は伏せた形で、一時フォルダーのパスは `<プロジェクト>` に置き換えた
- 費用は Claude Code が返した `total_cost_usd`。サブスクの枠で動いた見込みなので、請求の額ではなく目安

回したコマンド(見本を一時フォルダーに写して回した。`<見本の写し>` は写した先):

```sh
STUDIO_ALLOW_CLAUDE_CODE=1 npm run evals -- <見本の写し> --real --limit-usd 3 --judge-model claude-sonnet-5-5 \
  --composition composition.json,compositions/single-agent.json,compositions/master-sub.json
```

## 結論

- マスターとサブは、実モデルでも書いたとおりに動いた。荷物を調べる場面では、マスターが毎回荷物の係に任せ、係の結果で答えた。マスターは荷物のツールを持たないので、自分では引いていない
- 通った場面は、単一エージェントとマスターとサブが 10 本のうち 9 本、固定の流れが 8 本。3 つとも `escalate-unread` が通らなかった。固定の流れは、ほかに `redeliver-ok` の採点が通らなかった。この題材では、単一エージェントから分けても、通る場面は増えなかった。審査の判断の順(審査の設計の 2 節)なら、「マスターとサブは要らない(今日の推測)」になる
- 分けた分の費用と待ち時間は増えた。単一エージェントと比べ、費用は 2.3 倍、起動は 2.1 倍、返事の待ち時間の中央値は 2.6 倍
- 上限を超えた委任は、この回しでは起きなかった。1 ターンの委任は、どの場面でも 1 回だった。上限で止まる振る舞いは、モックと偽の `claude` のテストで確かめた(下の「確かめていないこと」)

## 分かったこと

- **委任の形は読める。** 記録(`run/traces/03-*.json`)の `delegations` と、模擬のエージェントの段の `depth`、`parent`、`round` で、誰が誰に任せ、どのツールを誰が呼んだかが 1 件ごとに分かる。例: `redeliver-ok` の「はい」のターンは、マスター → 予約の係(深さ 1)→ `record_consent`、`save_redelivery`(どちらも予約の係が呼んだ)→ 結果を受け取ったマスター
- **むだな書き込みが出た。** マスターとサブの `redeliver-ok` では、「はい」で予約の係が書いた後、次の「お願いします」でマスターがもう一度任せ、予約の係が同じ値で書き直した(むだな繰り返し 2)。単一エージェントでは起きなかった。マスターは前のターンにサブが書いたことを、会話の文でしか知らないため(推測)。記録の店の値は同じなので、場面の確かめは通る
- **人に渡す早さが変わった。** `escalate-not-found` で、マスターは 1 回目の「見つからない」で担当者へ引き継いだ。場面が見ているのは 2 回目の後の引き継ぎだが、確かめは引き継いだかだけなので通った。プロンプトの枠(`prompts/master-guide.md`)に「2 回」と書いていないため(推測)
- **3 つとも通らない場面がある。** `escalate-unread`(番号が 2 回読めないと担当者に渡す)は、どの形でも渡さなかった。固定の流れでは、2 回目の「えーと、どこだろう」を読み取りが質問(`clarify`)と読み、2.8 の決まりで回数に数えなかった。単一エージェントとマスターとサブでは、モデルが番号を聞き直し続けた。場面の書き方か数え方を見直すかは、人が決める。2026-11-08 に運営者が「数え方を直す」と決め、質問(`clarify`)も読めなかった回に数えるようにした。直した後、固定の流れでこの場面を実モデルで 3 回回し、3 回とも担当者に渡った。単一エージェントとマスターとサブは、数え方ではなくモデルの判断なので、この直しでは変わらない
- **固定の流れの採点が低かった。** `redeliver-ok` の自然さは 3 点で、理由は「番号を『1,001』と読みにくく表記し、返事が長め」。#419 の固定の流れの言い方の話で、委任とは関係しない

## 確かめていないこと

- 上限を超える委任を、実モデルで起こしていない。この回しでは、1 ターンの委任はどれも 1 回で、`limits.maxDelegations`(2)と `limits.maxDepth`(1)に当たらなかった。上限で止まることは、モックの `test/unit/delegate.test.js` と、偽の `claude` の `test/integration/delegate-claude.test.js` で確かめた
- サブに会話の全体を渡す辺(`history: true`)は、実モデルで回していない
- 1 回だけの回し(`--repeat 1`)。ぶれの大きさは測っていない
- 待ち時間は、同じ PC でほかの作業が動いている間に測った。長めに出ているかもしれない(推測)
