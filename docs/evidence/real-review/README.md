# AI 構成の審査の案を実モデルで出した記録

案を出す AI(`src/server/design-ai.js`)に、形の違う架空の題材 3 つを本物の AI で 1 回ずつ通した記録です。task 422。2026-11-08 に取りました(記録の時刻は UTC で 2026-11-07)。

**判定は、エージェントが読んだ下書きです。運営者が読んで、2026-11-10 に次のとおり決めました。**

- 案は使ってよい。案を出す AI は作り直さない
- 「仕事を分けて並べられる」題材で単一エージェントを勧めた判断を受け入れる
- Studio が書く構成にデータを引くツールが入らない問題は、別のカード jyoka/tasks#426 で直す(下の「残る問題」)

## 結論

- 3 題材で、勧めた構成は 2 種類だった。手順が決まっている題材は固定の流れ、残りの 2 つは単一エージェント。いつも同じ構成ではないので、作り直していない
- 仕事を分けて並べられる題材でも、マスターとサブは勧めなかった。「1 つの AI が 3 つの表を選んで引けば足りる」という理由で、問い 2 で止まった。設計の「足りたら止まる」と「上の形に進むには、下の形で通らない場面の id が要る」(ai-architecture-review.md の 2 節)には合う。ただし、マスターとサブを勧める題材を確かめられていない
- 実モデルの費用は合計 0.4109 USD(上限 3 USD)。3 題材とも 1 回の起動で、形の壊れた返事はなかった
- 案ごとの数は、Studio が書いた構成をお試しの AI(モック)で回した結果だけ。形の確かめで、案の良し悪しの根拠にしない。本物の AI では場面を回していない

## 読んで分かったこと(エージェントの読み)

- 理由は、どの問いで止まったかと、題材の言葉で書かれていた。プロンプトに足した「どの問いで止まったかを書く」「どの題材でも同じ形を勧めない」の指示に従っている
- 家電店の題材では、道具を選ぶ必要があると読めている。ただし、Studio が書く単一エージェントの構成には、道具(ツールの宣言)が入らない。お試しの AI の場面で道具を呼んだ回数は 0。データの表を道具で引く形は、作る AI が書くことになる。そのとき、ツールの宣言は承認した構成の指紋に入るので、関門 GA で止まり、審査に戻る(下の「残る問題」)
- 場面の段の「遅い」の場面に、使う人の発言ではない文(「(土日の空きを全部まとめて聞かれ、確かめるのに時間がかかる)」)が 1 つ出た(市民プール)。前からの場面の段の問題で、今回は直していない
- 市民プールの「断る」の場面は、決まり(7 日先まで、2 人まで)を超える頼みになっていた。決まりを場面にしている

## 残る問題

- マスターとサブを勧める題材は確かめていない。仕事を分けると通らない場面が通る、という数がないと勧めないのが設計の順なので、本物の AI で単一エージェントの場面を回し、通らない場面がある題材で確かめる必要がある
- Studio が書く単一エージェントとマスターとサブの構成には、データを引くツールが入らない。作る AI がツールを足すと、承認と違う構成として止まる。このカードでは直さず、別のカード jyoka/tasks#426 で直す(運営者の決定、2026-11-10)。Studio がデータ設計からツールの宣言も書くか、ツールを足す依頼を審査の中で受けるかは、#426 で決める。2026-11-11 に #426 で、Studio がデータ設計から書く形で直した([ai-architecture-review.md の 16 節](../../design/ai-architecture-review.md#16-426-で決めたこと))。この記録の数は直す前のもの
- 本物の AI で場面を回した数(費用、待ち時間、道具の正しさ)はない。審査の画面では「まだ測っていない」と出る

## 確かめていないこと

- 同じ題材を何回も通したときのぶれ(各 1 回だけ)
- 画面からの通し(スクリプトは Studio の同じコードを使うが、ブラウザーと HTTP の層は通らない)
- 人が案を読んで理解できるか
